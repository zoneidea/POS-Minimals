# Shared action feedback — 2026-10-14

SweetAlert2 handles saved-data notifications, mutation confirmation and action errors across store/payment/printer settings, products/categories, stock adjustments, staff invitations/changes/removal, Excel imports, sales/cancellation and account/password forms. Success has a 1500 ms timer, progress bar and no confirmation button. Warning dialogs display textual action/validation errors. Modifications are confirmed before mutation; creation forms save directly and notify only after success. Deleting products/categories/members uses a shared SweetAlert confirmation instead of duplicate native confirmation Modals. Existing soft-delete APIs and financial idempotency/recovery remain in place.

Shared helpers are in apps/web/src/lib/alerts.ts and use-action-feedback.ts. SweetAlert targets an open native dialog when present so its controls remain accessible above Modal forms. Confirm defaults focus to Cancel; cancelling does not call the mutation. If the alert chunk cannot load, mutation confirmation fails closed; success/warning feedback does not change saved business results. Form error context remains available where needed for recovery. Existing read-page loading/error/empty rendering is retained. Persistent product/category success banners are removed in favor of timed success dialogs.

Bank selector, masked account number and replacement input share one aligned desktop row, with wrapping on narrow viewports. Accountant views remain read-only and numbers stay masked; no bank payload or permission change is introduced.

Verification: typecheck/build passed; three shared-dialog tests pass for 1500 ms configuration, cancelled confirmation and native-dialog target. Payment API/SQL tests (6) pass when run in isolation; an earlier combined run timed out during PGlite initialization, with no assertion failure. Isolated browser fixtures verified confirmation Cancel, successful save auto-close, warning on invalid data, category-edit native Modal overlay, delete confirmation and accountant bank layout. No live business data was modified for UI QA. Screenshots are in /tmp/pos-sweetalert-confirm.png, /tmp/pos-sweetalert-success.png, /tmp/pos-sweetalert-warning.png and /tmp/pos-sweetalert-delete.png.
