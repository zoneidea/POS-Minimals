# 06 — PostgreSQL / Supabase Database Design

> **Implementation scope (Phase 1, 2026-10-11):** พัฒนาเฉพาะ **React Web App + Node.js/Express API + Supabase** ใน Repository [`zoneidea/POS-Minimals`](https://github.com/zoneidea/POS-Minimals). JavaFX Desktop และ Native Mobile App **ยังไม่ต้องพัฒนา ไม่ต้องสร้าง SDK/Installer หรือเพิ่มเป็น Gate ใน CI/UAT รอบนี้**; ออกแบบ API ให้ขยายในอนาคตได้เท่านั้น.

## 1. Guiding conventions
- DB engine: Supabase PostgreSQL; `auth.users` เป็น source of truth สำหรับ identity; ไม่สร้างตาราง plaintext passwords
- ทุกตารางข้อมูลธุรกิจมี `org_id UUID NOT NULL` (ยกเว้น global auth identity), อ้างอิง `organizations(id)`
- PK = UUID, `created_at/updated_at TIMESTAMPTZ`, `created_by/updated_by UUID`, master มี `deleted_at/deleted_by`
- เงิน: `NUMERIC(14,2)` PostgreSQL; `>=0`; ส่ง API เป็น string decimal หรือ parse อย่างปลอดภัย ห้ามอาศัย JS float สำหรับคำนวณชำระเงินจริง
- Stock qty: `INTEGER >= 0`, MVP ไม่มีเศษหน่วย
- `row_version BIGINT DEFAULT 1` สำหรับ optimistic lock บน product
- ใช้ `org_id` + `id` เป็น composite unique key สำหรับ FK ข้าม table ป้องกัน record A ของ org 1 ชี้ record B ของ org 2

## 2. Entity relationships (conceptual)
```text
auth.users ──< organization_members >── organizations
                                         ├── store_settings (1:1)
                                         ├── categories ──< products
                                         ├── products ──< stock_movements
                                         ├── sales ──< sale_items >── products (nullable historical reference)
                                         │     └── payments
                                         ├── product_audit_logs
                                         └── idempotency_records
```

## 3. Tables and columns

### `organizations`
- `id UUID PK` (ORGID, generated by DB)
- `name TEXT NOT NULL`, `status TEXT` (`ACTIVE/SUSPENDED`)
- `created_at TIMESTAMPTZ`; `deleted_at TIMESTAMPTZ NULL`
- UUID uniquely generated; never use user-supplied org id for new org

### `organization_members`
- `id UUID PK`, `org_id UUID NOT NULL`, `user_id UUID NOT NULL REFERENCES auth.users(id)`
- `display_username TEXT NOT NULL` (**not unique**)
- `role TEXT NOT NULL CHECK (role IN ('OWNER','EMPLOYEE','ACCOUNTANT'))`
- `status TEXT NOT NULL CHECK (status IN ('INVITED','ACTIVE','SUSPENDED'))`
- `joined_at`, `deleted_at`, `created_at`; unique (`org_id`,`user_id`) including soft deleted as appropriate for reactivation
- MVP policy: one active membership per `user_id` across all orgs (partial unique index on `user_id WHERE status='ACTIVE' AND deleted_at IS NULL`); relax in later multi-org version

### `store_settings`
- `org_id UUID PK REFERENCES organizations(id)`
- `store_name`, `address`, `phone`, `tax_id`, `receipt_footer`, `logo_path`
- `vat_enabled BOOLEAN DEFAULT FALSE`, `vat_rate NUMERIC(5,2) DEFAULT 7.00` (rate configurable; not legal advice)
- `vat_mode TEXT DEFAULT 'INCLUSIVE'` (MVP fixed inclusive)
- `promptpay_identifier TEXT` (mask on read as appropriate), `auto_open_print_dialog BOOLEAN DEFAULT TRUE`
- `updated_at`, `updated_by`, `deleted_at`

### `categories`
- `id UUID PK`, `org_id UUID`, `name TEXT NOT NULL`, `sort_order INTEGER DEFAULT 0`
- `created_at`, `updated_at`, `deleted_at`, `deleted_by`
- active unique `(org_id, lower(trim(name)))` recommended expression partial index `WHERE deleted_at IS NULL`

### `products`
- `id UUID PK`, `org_id UUID`, `category_id UUID` (+ composite FK to categories)
- `barcode TEXT NOT NULL`, `name TEXT NOT NULL`, `image_path TEXT NULL`
- `sale_price NUMERIC(14,2) NOT NULL DEFAULT 0 CHECK >=0`
- `unit_cost NUMERIC(14,2) NOT NULL DEFAULT 0 CHECK >=0`
- `quantity_on_hand INTEGER NOT NULL DEFAULT 0 CHECK >=0`
- `row_version BIGINT NOT NULL DEFAULT 1`
- `created_at`, `updated_at`, `deleted_at`, `created_by`, `updated_by`, `deleted_by`
- **UNIQUE (`org_id`, `barcode`) รวม soft-deleted records**; barcode trim/canonicalization ก่อน insert (preserve leading zeros)
- indexes: `(org_id, deleted_at, category_id)`, `(org_id, deleted_at, name)`, `(org_id, quantity_on_hand)`; trigram search เมื่อจำเป็นหลัง benchmark
- Unique `(org_id,id)` เพื่ออ้างอิง composite FK

### `sales`
- `id UUID PK`, `org_id UUID`, `sale_no TEXT NOT NULL`, `cashier_member_id UUID NOT NULL`
- `cashier_name_snapshot TEXT NOT NULL`
- `status TEXT CHECK ('COMPLETED','VOIDED')`
- `subtotal`, `discount_amount`, `vat_amount`, `net_before_vat`, `total_amount` NUMERIC(14,2)
- `vat_enabled_snapshot`, `vat_rate_snapshot`, `vat_mode_snapshot`
- `store_name_snapshot`, `store_address_snapshot`, `store_phone_snapshot`, `store_tax_id_snapshot`, `receipt_footer_snapshot`
- `completed_at TIMESTAMPTZ NOT NULL DEFAULT now()`
- `voided_at NULL`, `voided_by NULL`, `void_reason NULL`
- `idempotency_key UUID NOT NULL`, `request_hash TEXT NOT NULL`
- Unique (`org_id`, `sale_no`), unique (`org_id`, `idempotency_key`)
- indexes `(org_id, completed_at DESC)`, `(org_id, cashier_member_id, completed_at DESC)`, `(org_id, status, completed_at DESC)`
- Never soft delete sale; status transition provides audit-safe equivalent

### `sale_items`
- `id UUID PK`, `org_id UUID`, `sale_id UUID`, `product_id UUID NULL` (history survives product soft deletion)
- `product_name_snapshot TEXT NOT NULL`, `barcode_snapshot TEXT NOT NULL`
- `category_name_snapshot TEXT NULL`, `quantity INTEGER NOT NULL CHECK >0`
- `unit_price_snapshot`, `unit_cost_snapshot`, `gross_line_amount`, `discount_allocated`, `net_line_amount`, `vat_allocated` NUMERIC(14,2)
- `created_at`
- composite FK `(org_id,sale_id)` to sales; `(org_id,product_id)` to products when set
- indexes `(org_id, sale_id)`, `(org_id, product_id)`

### `payments`
- `id UUID PK`, `org_id UUID`, `sale_id UUID`, `method TEXT CHECK ('CASH','PROMPTPAY')`
- `status TEXT CHECK ('CONFIRMED','MANUALLY_CONFIRMED')`
- `amount NUMERIC(14,2) NOT NULL`, `received_amount NUMERIC(14,2)`, `change_amount NUMERIC(14,2)`
- `confirmed_by UUID NOT NULL`, `confirmed_at TIMESTAMPTZ NOT NULL`
- `created_at`; unique `(org_id,sale_id)` for MVP single payment per sale
- Payment is a record of cashier assertion, NOT proof of money settlement for PromptPay

### `stock_movements`
- `id UUID PK`, `org_id UUID`, `product_id UUID`, `movement_type TEXT` (`SALE_OUT`, `SALE_VOID_IN`, `ADJUST_IN`, `ADJUST_OUT`, `IMPORT_INITIAL`)
- `quantity_delta INTEGER NOT NULL CHECK <>0`, `quantity_before`, `quantity_after` INTEGER CHECK >=0
- `sale_id UUID NULL`, `reason TEXT NULL`, `performed_by UUID NOT NULL`, `created_at`
- `reverses_movement_id UUID NULL`, unique where non-null to prevent duplicate compensations
- indexes `(org_id, product_id, created_at DESC)`, `(org_id, sale_id)`
- Append-only; quantity_before + quantity_delta = quantity_after validated in transaction

### `product_audit_logs`
- `id UUID PK`, `org_id UUID`, `product_id UUID`, `action TEXT` (`CREATE`,`UPDATE`,`STOCK_ADJUST`,`DELETE`,`REVERSE`,`IMPORT`)
- `before_json JSONB`, `after_json JSONB` (selected product fields + qty when relevant)
- `before_version BIGINT NULL`, `after_version BIGINT NOT NULL`, `actor_user_id UUID NOT NULL`
- `reason TEXT NULL`, `reversed_event_id UUID NULL`, `created_at`
- indexes `(org_id, product_id, created_at DESC)`, `(org_id, created_at DESC)`
- Append-only; protect from client direct writes; log PII only when necessary

### `idempotency_records` (optional as separate control table)
- `id UUID PK`, `org_id UUID`, `key UUID`, `action TEXT`, `request_hash TEXT`, `status`, `result_json JSONB`, `created_at`, `completed_at`
- unique (`org_id`, `action`, `key`)
- Checkout unique key in `sales` may suffice, but separate record helps concurrent in-progress and failures; lifecycle needs one transaction boundary

### `invitations` (owner user management)
- `id UUID PK`, `org_id UUID`, `email_normalized TEXT`, `role TEXT`, `status TEXT`, `expires_at`, `created_by`
- secure one-time token stored **hashed**; no plaintext tokens persisted; soft-delete as master record

## 4. SQL constraints / indexes blueprint (illustrative)
```sql
CREATE UNIQUE INDEX products_org_barcode_uniq
  ON public.products (org_id, barcode); -- including soft-deleted rows

CREATE UNIQUE INDEX members_org_user_uniq
  ON public.organization_members (org_id, user_id);

CREATE UNIQUE INDEX products_org_id_uniq
  ON public.products (org_id, id);

ALTER TABLE public.products
  ADD CONSTRAINT products_quantity_nonnegative CHECK (quantity_on_hand >= 0);

-- Example only: also define composite FK for org-safe relationships
ALTER TABLE public.products
  ADD CONSTRAINT products_category_same_org
  FOREIGN KEY (org_id, category_id)
  REFERENCES public.categories (org_id, id);
```
**Important:** Migration order must create required parent UNIQUE `(org_id,id)` before composite foreign keys; script above is blueprint, not drop-in full migration.

## 5. RLS design baseline
- Enable RLS for every exposed org-scoped table and Storage policies for `product-images/<orgId>/...`
- `SELECT` products for active OWNER and EMPLOYEE; reports via restricted aggregate functions for ACCOUNTANT
- `INSERT/UPDATE` product/category/settings only OWNER; do not grant direct update for inventory qty and ledgers
- `sales`, `payments`, `stock_movements`, `product_audit_logs`: **no direct writes** by browser / generic REST table routes; only narrowly granted transactions/functions
- Functions with `SECURITY DEFINER` must set locked `search_path`, verify caller `auth.uid()` and active org membership/role explicitly, restrict GRANT EXECUTE, validate all passed ids against org

**Policy pseudocode**
```sql
-- SELECT policy idea (complete actual migrations with indexes/GRANTs):
USING (
  EXISTS (
    SELECT 1 FROM public.organization_members m
    WHERE m.org_id = products.org_id
      AND m.user_id = (SELECT auth.uid())
      AND m.status = 'ACTIVE' AND m.deleted_at IS NULL
      AND m.role IN ('OWNER', 'EMPLOYEE')
  )
)
```
- For ACCOUNTANT avoid direct access to product cost if not necessary; reports must use owner/accountant guard.
- Test SELECT/INSERT/UPDATE/DELETE allow/deny for 2 separate orgs, anonymous and suspended members.

## 6. Required DB transactions / RPCs
### `checkout_sale(org_id, items[], discount_amount, method, received_amount, idempotency_key)`
- `auth.uid()` + membership validation, role OWNER/EMPLOYEE
- Validate payload, unique idempotency key/request hash, `FOR UPDATE` on products sorted by id
- Read latest prices, stock and store settings; recalculate totals exactly; compare client `expectedUnitPrice` for each item and `expectedTotalAmount` against latest server values, otherwise abort `CART_STALE`
- Check cash received >= total / PromptPay manually confirmed; protect no negative stock
- Insert sale, items snapshots, payment, stock_movements, update products quantity/version, return complete receipt view
- DB transaction all-or-nothing; avoid magic retry on errors with ambiguous SQLSTATE

### `void_sale(org_id, sale_id, reason)`
- only OWNER; lock sale FOR UPDATE, check completed + now <= completed_at + interval '24 hours'
- lock affected products sorted by id; compensating positive stock movements and update quantities
- mark sale VOIDED + audit metadata; idempotent duplicate void should return already voided without extra stock

### `adjust_stock(org_id, product_id, delta, reason, expected_version)`
- OWNER only, lock row, check nonnegative; create movement, increment version, append audit before/after

### `reverse_product_change(org_id, audit_id, reason)`
- OWNER only; verify latest version, prevent duplicate reverse, create compensating data/movements and new audit event

## 7. Reporting queries
- Sales report: aggregate `sales` filtered `status='COMPLETED'` by Bangkok-aligned UTC range, optionally cashier member; historic item/product names from `sale_items.*_snapshot`
- Stock: current products `deleted_at IS NULL`; low stock `quantity_on_hand <= 5`
- Stock valuation: `SUM(quantity_on_hand * unit_cost)` current value as-of now
- Report export filters exactly match on-screen filters, authorization rechecked server-side

## 8. Retention, deletion, restoring
- Master soft-delete fields, default active-only views; no cascade physical deletion from org to historical ledgers
- Logs/sale snapshots append-only at application layer with restricted DB grants
- Reverse creates new transaction/log, never erases history; database backups are independent of app audit


## 11. Cross-Client Consistency (Web/JavaFX/Mobile)
- **No DB schema fork per client.** Same `organizations`, `organization_members`, `products`, `sales`, `sale_items`, `payments`, `stock_movements`, `audit` and `idempotency_records` are shared across all platforms.
- `client_platform` (`WEB`, `JAVAFX`, `ANDROID`, `IOS`, `OTHER`) and `client_version` may be nullable observability metadata on sale/event records; server must not use them for access control or price calculation.
- Save optional immutable `device_reference` opaque ID for correlation if necessary; don't use it as user auth; do not create separate device-bound stock sources or offline sale databases in MVP.
- `idempotency_records` unique `(org_id, action_type, idempotency_key)`, request hash, saved response/status, actor; client-generated UUID per logical mutation. All clients use same global server-side collision handling.
- Receipt snapshot must be API-ready JSON-serializable data with version identifier (`receipt_schema_version` = 1) independent of printer commands, CSS and Java classes.
- All snapshots and transaction functions resolve membership/role **on the DB/server side**; type conversions from Java BigDecimal/JS decimal strings must not round the monetary values in transport.

## Identity migration implemented (2026-10-11)

`supabase/migrations/202610110001_identity_tenants.sql` implements organizations, memberships, store settings and `activity_logs` (org, actor, action, entity, request ID, timestamp; no credentials/payloads). Managed Supabase encryption at rest and TLS are required for actual hosting as described in `08_SECURITY_TENANCY.md`; PGlite fixtures contain synthetic identities only.

`private.current_org_role(uuid)` is a fixed-search-path SECURITY DEFINER helper to avoid recursive membership policies. Only active members of an active organization receive a role. OWNER reads own-org membership/settings/activity; other roles read their own membership and org only. All authenticated/anonymous direct writes are denied; later management mutations need separately authorized RPCs.

`bootstrap_org` validates auth.uid and verified email, takes a per-user transaction advisory lock, creates org/OWNER/settings/activity in one transaction, and returns the existing OWNER org on retry. Any existing suspended/deleted membership blocks re-provisioning; EMPLOYEE/ACCOUNTANT cannot bootstrap a second org.

Migration history lives in private.schema_migrations. The initializer uses a migration advisory lock and checksum verification. No destructive down migration is supplied; code rollback retains the additive schema. Hosted integration and multi-session lock proofs remain required before release.
